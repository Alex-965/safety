## Виконання без Linux на персональному комп'ютері

Практичні команди виконує GitHub Actions на одноразовій Ubuntu 24.04.
Нічого встановлювати у Windows не потрібно. Workflow міститься у репозиторії
Alex-965/safety: `.github/workflows/labs-4-5.yml`. Для повторення відкрити
Actions -> Labs 4 and 5 verified execution -> Run workflow.
Після завершення завантажити артефакт `lab4-lab5-execution`.

`run_lab4.py` відмовляється працювати поза Linux GitHub Actions та за наявності
облікових записів jenny/kobzei або групи HR. Він змінює тільки одноразовий runner.
Не запускайте його на персональному чи робочому Linux-сервері.
Паролі lasocial і tooth задані методичкою та використовуються лише в цьому стенді.

## Вміст

- `run_lab4.py`: команди та перевірки, включно з реальним su через PAM.
- `requirements.txt`: pexpect для введення пароля у псевдотермінал.
- `results/`: оригінальні журнали й машинозчитувані результати.
- `screenshots/`: повноекранні знімки переглядача термінального журналу.
- `report.docx`: звіт із титулкою та поясненнями.

## Відмінності від старої інструкції

1. Замість Cisco Ubuntu 16.04 використовується Ubuntu 24.04 на віддаленому runner.
   GitHub створює тимчасову віртуальну машину у хмарі, а не на вашому ПК.
2. Замість joe використовується kobzei; jenny збережена.
3. TTY1/TTY2 і GUI замінені su, runuser та sudo: це ті самі користувачі й реальні
   перевірки Linux DAC, без перемикання графічної консолі.
4. Сучасний adduser створює домашні каталоги з обмеженішими правами. Для
   початкового експерименту явно встановлено 755, далі 754 через o-x, потім 705.
5. Використано ASCII дефіс і usermod -aG HR, щоб зберегти інші додаткові групи.
6. `sudo -l joe` з методички не виконує вхід: правильна команда `su - kobzei`.
7. Група каталогу залишається kobzei. Якби це була HR, членство Jenny у HR
   застосувало б групові біти 0 у режимі 705 і доступу не було б. Це перевіряється окремо.
8. UID/GID призначаються системою; значення 1005 з прикладу не зафіксоване.
9. Runner додає ACL до нових домашніх каталогів. Вони спочатку записуються через
   getfacl, потім setfacl -b -k прибирає їх тільки з jenny/kobzei, щоб експеримент
   перевіряв звичайні POSIX-біти. Файл test.txt створюється з umask 022.

Журнали містять справжні команди, stdout/stderr та коди повернення. Знімки
переглядача створюються з цих даних, а не з намальованих очікуваних результатів.
