## Запуск у Windows

Потрібен Python 3.10 або новіший. Подвійний клік `Start-Lab5.cmd`, або:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py
.\.venv\Scripts\python.exe -m unittest -v test_crypto
```

Linux чи віртуальна машина не потрібні. Програма також перевіряється на
віддаленій Ubuntu у workflow `.github/workflows/labs-4-5.yml`.

## Завдання

1. Цезар: повний перебір ключів 0–25 для vppanlwxlyopyncjae.
   Ключ 11 дає keepcalmandencrypt. Автоматичний перебір видає всіх кандидатів;
   осмислений англійський варіант вибрано за змістом і перевірено зворотним шифруванням.
2. Віженер: український алфавіт з 33 літерами включно з ґ, є, і, ї;
   ключ кобзей; приклад з умови. Латинська i у вхідному прикладі нормалізується
   в українську і; це явно відображено у результатах. Регістр і пунктуація зберігаються,
   ключ рухається тільки на українських літерах. Інші символи копіюються.
3. RSA: генерація p і q через secrets та Міллера Рабіна з 40 раундами;
   n має 2048 біт; e=65537; d обчислюється як модульний обернений до e за phi(n).
   Окремі функції шифрують і розшифровують число M=100.
4. Текстовий RSA: UTF-8, OAEP SHA-256, блоки до 190 байт, RSA-блоки 256 байт,
   об'єднання в Base64. Розшифрування спочатку об'єднує байти і лише потім декодує
   UTF-8, тому багатобайтова літера може перетинати межу блоків. Довжина рядка
   не обмежена одним RSA-блоком, але використання пам'яті залежить від обсягу даних.

## Файли

- `crypto_lab.py`: функції, генерація ключів, OAEP і Base64.
- `demo.py`: усі задані приклади та додаткові UTF-8/порожній/довгий рядки.
- `test_crypto.py`: 12 тестів, зокрема межі блоків, неправильний Base64,
  пошкоджений шифротекст, випадковість OAEP та коректність ключів.
- `results/`: справжні результати одного запуску; `results-run.log`, `tests-run.log`.
- `screenshots/`: знімки переглядача фактичних результатів.
- `report.docx`: звіт із титульною сторінкою за наданим шаблоном.

## Навчальні межі

Цезар і Віженер є історичними шифрами. RSA для числа навмисно демонструє
математичні операції без padding. У завданні 4 використано OAEP, рекомендований
для нових RSA-застосувань, але незалежне блокове шифрування не автентифікує
порядок/кількість блоків або особу відправника. Для робочих протоколів потрібні
перевірені гібридні схеми з автентифікацією. Base64 є кодуванням, а не шифруванням.

`results.json` містить p, q і d виключно одноразового навчального ключа, щоб
перевірити обчислення у звіті. Не використовуйте ці ключі для справжніх даних.
Повторний запуск генерує нові ключі й OAEP-випадковість, тому RSA-криптотекст зміниться.
