## Запуск на Windows

Потрібен Python 3.12 або новіший. Команди виконують у корені репозиторію:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_local.py
```

Відкрити http://127.0.0.1:5000. Зупинка обох сервісів: Ctrl+C.
Після встановлення залежностей можна також запустити `Start-Lab6.cmd`: він
використовує Python із `.venv`, якщо середовище створене, або системний Python.
Перший запуск створює `instance/` із базою та випадковими локальними ключами.
Адміністратора створити в іншому терміналі:

```powershell
.\.venv\Scripts\python.exe -m flask --app app:create_app create-admin
```

Пароль вводиться приховано; потрібні 8+ символів, великі/малі літери,
цифра й спеціальний символ. У вихідному проєкті немає стандартного адміністратора.
Зареєструвати власний тестовий акаунт, перейти до «Тестова пошта», відкрити
посилання та підтвердити активацію. Не вводити справжні персональні дані.

## Реалізація

1. Політика паролів на сервері, scrypt:32768:8:1 з випадковою сіллю, профіль і вихід.
2. Графічна CAPTCHA: випадкові 5 символів, одноразова відповідь, 120 секунд.
3. Активація: криптографічний токен, SHA-256-хеш у БД, строк 15 хвилин.
4. Після 5 неправильних паролів блокування на 300 секунд; ліміти за IP;
   журнал UTC/IP/email/результат; адміністратор блокує й розблоковує користувачів.
5. TOTP: 6 цифр, крок 30 секунд; підтвердження налаштування; зашифрований секрет;
   заборона повторного коду в тому самому інтервалі; 5 спроб за 5 хвилин.
   Вимкнення: поточний пароль і TOTP. Відновлення пароля зберігає 2FA.
6. Authlib OIDC Authorization Code + PKCE S256; state, nonce, RS256 ID token;
   локальний провайдер `idp.py` на порту 5001. Користувач визначається через
   пару issuer/sub. Автоматичного зв'язування локального акаунта за email немає.
7. Відновлення: одноразовий токен на 15 хвилин; однакове повідомлення для відомого
   й невідомого email; перевірка нового пароля; відкликання попередніх сесій.

Додатково: CSRF для POST, HttpOnly/SameSite cookie, CSP, no-store, параметризований
SQL, обмеження розміру запиту, серверна перевірка ролі та стану акаунта.

## Локальний стенд та зовнішні сервіси

`DEMO=True` означає, що листи потрапляють у локальний outbox, доступний через
`/mail` лише з loopback. Справжня доставка email не перевірялася.
Local Lab ID реалізує обмін кодами та перевірку PKCE і видає підписаний ID token,
але дозволяє підтвердити наперед визначену тестову особу без реальної перевірки
ідентичності. Це **тестовий провайдер**, його не можна публікувати як сервіс входу.

Для Google або іншого довіреного OIDC-сервісу зареєструвати клієнта,
налаштувати callback та змінні `OIDC_METADATA`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`.
Клієнтські секрети вводити лише локально, не в чат і не в репозиторій.
Зовнішній запуск потребує HTTPS, `SESSION_COOKIE_SECURE=True`, `DEMO=False`,
фіксованої довіреної адреси застосунку та сховища секретів. Для SMTP_SSL реалізовано
відправлення через `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`.
Не запускати `/mail`, тестовий IdP та Flask development server у відкритій мережі.
Проста CAPTCHA не замінює промисловий антибот-сервіс. Ліміти навчального стенда
потребують очищення/масштабування у робочій інфраструктурі.

відкликання сесій, нерозкриття email та HTTP-заголовки. Окремий ізольований
браузерний сценарій пройшов повний цикл, включно з реальним OIDC-обміном між
двома локальними процесами; збережено 19 знімків інтерфейсу.
